## Derived implementation rules

1. **Model eligibility:** fetch text-output catalog records, require text input/output, non-expired metadata, sufficient context for the bounded snapshot, and `structured_outputs` or `response_format` support. Calculate an estimated call cost from live `prompt`, `completion`, and `request` prices at fixed input/output budgets. Choose the lowest eligible value as the default, show the timestamp/prices, and allow user selection from the same filtered list.
2. **Exclusions:** apply normalized matching to model ID, canonical slug, and name. Reject GPT generation `>=6` and the exact Claude Fable generation `>=5`; do not silently broaden “Claude Fable” into all Claude families. Apply the same predicate to UI options and immediately before POST. Unknown metadata fails closed.
3. **Key handling:** OpenRouter’s warning means the `.env` token must not be placed in `manifest.json`, JavaScript, ZIP, Web Store item, logs, screenshots, or chat. A local/session-only import or explicit password-style entry is acceptable for this private MVP only after the pending choice is resolved; session storage is not encrypted and does not protect a machine owner. Rotate a key if exposed.
4. **Privacy/distribution answer:** For a personal/private build, load the unpacked extension locally in Developer mode and keep the directory/ZIP private. If store distribution is later needed, choose Private for named testers or Unlisted for link-only access; neither makes code or a client-side key secret, and both still face Chrome policy/review. Do not publish the token.
5. **Shopee boundary:** no official Shopee API evidence was needed or used. The adapter is rendered-DOM-only, synthetic interaction, and live-unverified until coordinator-controlled browser evidence. CAPTCHA, login, payment, checkout, bot defenses, hidden endpoints, and credential extraction are out of scope.
